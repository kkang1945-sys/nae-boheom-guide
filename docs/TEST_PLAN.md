## 테스트 층

- 단위: 금액 단위, 보험/납입기간, 갱신, 주계약/특약, 지급 방식, 담보 매핑·합산, 계산식, 판단 보류, 확정값 우선
- 통합: 여러 PDF 업로드, 원문 연결, 수정·확정, 통합, 입력, 분석, 버전 저장, 재분석, 삭제
- 종단간: 업로드 → 추출 → 확인 → 통합 → 입력 → 분석 → 근거 → 저장 → 재분석 → 내보내기 → 삭제
- 회귀: 실제 PDF에서 발견한 오류를 합성 또는 승인된 익명화 사례로 고정
- 화면: PC에서 원문 확인·표 수정·삭제. D-011에 따라 휴대전화는 결과 PDF 열람을 우선하며 모바일 전용 업로드·수정 검수는 향후 작업이다.

## 분석 직전 검산 테스트

- 모든 계산 대상 담보에 사용자 확정값과 원문 근거가 있는가
- 정규화 금액을 원문 단위에서 다시 계산해 같은 값이 나오는가
- 보험기간·납입기간·갱신·지급 횟수의 미확정값이 없는가
- 실손과 정액형 또는 범위가 다른 담보가 합산 목록에 없는가
- 문서 해시, 담보 표·행 위치와 후보 수에 중복·누락이 없는가
- 검산 실패 상태에서는 분석 실행과 결과 저장이 차단되는가

## 실제 PDF 검수

최초 검수부터 사용자의 실제 보험 PDF를 한 개씩 사용한다. 앱이 먼저 원문과 추출값을 검산하고, 사용자는 읽기 불일치나 원문으로 해소하지 못한 예외를 확인한다. 개발 단계의 정답 표본 검수는 별도로 수행하며 이를 일반 사용자의 전수 확인 절차로 강제하지 않는다. 품질은 정확/오류/미검출/불필요 추출로 기록하고 보험사, 텍스트·스캔, 필드, 신뢰도별로 나눈다. 금액·단위·기간 오류는 치명 오류로 별도 집계한다.
