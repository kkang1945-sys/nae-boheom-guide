# 데이터 모델

## 조건 원문 근거

`PolicyConditionEvidence`는 PDF 담보 또는 문서 공통 조건의 원문 근거를 저장한다. 현재는 원문 위치가 검산된 담보의 보장내용 셀만 생성한다. 문서·담보 ID, 페이지·칸 좌표, 원문, 원본 기반 지문, 자동 분류/사용자 확인 상태와 추출기 버전을 분리해 보존한다. 자동 근거는 계산값이나 확정 담보값으로 취급하지 않는다.

2026-09-04 확장: `OcrPageResult`는 페이지별 원본 해시·엔진·언어·DPI·글자·좌표·상태를 저장한다. `DocumentMetadataRevision`은 보험회사·상품의 후보와 사용자 확정값을 분리해 변경 이력을 보존한다. 문서 공통 조건 후보는 `coverage_id=None`으로 저장하고 특정 담보에 자동 적용하지 않는다.

구현 스택과 무관한 논리 모델이다.

```text
AnalysisCase
 ├─ AnalysisSubject ─ InsuranceDocument[]
 │   ├─ DocumentPage[]
 │   ├─ ExtractionRun[]
 │   └─ Policy[] ─ Coverage[] ─ EvidenceRef[]
 ├─ FinancialProfileSnapshot[]
 ├─ AnalysisRun[] ─ RiskResult[] ─ CalculationStep[]
 └─ AuditEvent[]
```

## 핵심 엔터티

현재 구현 범위(2026-09-03): 문서·HWPML 담보·PDF 페이지와 `PdfCoverage`, `PdfExtractionRun`, `PdfCoverageRevision`, `PdfAudit`이다. 전체 논리 모델의 구현 완료를 뜻하지 않는다. PDF 페이지 글자·단어 좌표·크기·회전·읽기 상태와 추출 버전을 저장하고, PDF 담보에는 원문 셀/좌표·추출값·사용자값·변경 전후 이력을 보존한다. OCR값·HWPML 수정 이력·문서 메타정보 확인 이력은 후속 구현이다.

- `AnalysisCase`: 분석 건, 상태, 대상자·문서·입력·분석 버전 연결
- `AnalysisSubject`: 한 번에 분석할 한 사람의 구분용 이름, 관계, 선택적 출생연도, 생애단계, 경제적 역할, 성별 관련 및 임신·출산 관련 담보 검토 범위. 인구집단 평균이나 권장 보험금은 저장하지 않는다.
- `InsuranceDocument`: 원본 파일명, MIME, 크기, 해시, 저장 식별자, 페이지 수, 텍스트/스캔 판정, 처리·삭제 상태
- `DocumentPage`: 문서와 1부터 시작하는 페이지 번호
- `EvidenceRef`: 페이지·원문 좌표/발췌, 계약/사용자 입력/공식 출처/앱 가정 구분. 공식 출처는 기관·제목·URL·기준일·확인일 포함
- `ExtractionRun`: 추출기·OCR·프롬프트·규칙 버전, 상태·오류, 외부 전송 범위, 후보값·신뢰도·근거
- `Policy`: 보험회사, 상품명, 최소화·마스킹한 식별정보, 보험·납입기간, 계약 상태
- `Coverage`: 원문명, 표준 담보, 매핑 근거·버전, 급부, 정액/실손, 주계약/특약, 원문 금액·단위·통화, 정규화 금액, 기간·갱신, 지급 방식, 면책·감액·제외 조건, 확인 상태와 근거
- `FieldRevision`: 원본 후보를 보존한 채 이전값·새값·출처·시각·수정 이유 기록
- `FinancialProfileSnapshot`: 전체 경제정보, 단위, 사용 범위, 시나리오. 분석 후 불변
- `AnalysisRun`: 입력·담보·규칙 버전, 이전 결과를 덮지 않는 분석 버전
- `RiskResult`: 위험 영역, 상태, 필요·대응·공백 금액, 포함·제외 이유, 가정·한계·근거
- `CalculationStep`: 읽을 수 있는 식, 피연산자 값·단위·출처, 결과·반올림
- `AuditEvent`: 업로드·확정·분석·내보내기·삭제의 종류·대상 ID·시각·결과만 기록

## 공통 상태

- 확인: `unreviewed`, `needs_review`, `confirmed`, `rejected`, `not_applicable`
- 값 출처: `extracted`, `auto_checked`(별도 감사 기록), `user_confirmed`, `derived`, `official_reference`
- 처리: `queued`, `processing`, `succeeded`, `failed`, `cancelled`
- 삭제: `active`, `pending`, `deleted`, `failed`

## 불변 조건

- 모든 담보는 원문명과 원문 근거를 보존한다.
- 정규화 금액에는 원문 숫자와 단위가 있어야 한다.
- 사용자 확정값은 원본 추출값을 덮어쓰지 않는다.
- 분석 결과는 입력·담보·규칙 버전 없이 저장할 수 없다.
- 보험증권의 대상자가 미지정이면 계산에서 제외한다. 아동은 보호자 소득·돌봄비, 은퇴·고령기는 지속소득·돌봄비가 없으면 계산을 보류한다.
- 같은 계약으로 검증된 조회자료 묶음은 사용자의 명시적 선택으로 한 대상자에게 함께 연결한다. 해시 지문으로 대상자를 추측하지 않으며 같은 계약의 중복 담보를 여러 보험의 대응자금처럼 합산하지 않는다.
- 삭제된 원본 근거는 접근 불가 상태를 표시한다.
- 전체 삭제 결과는 공개한 보관·백업 정책과 일치해야 한다.

## 구현 추가: FinancialProfile (2026-09-07)

`FinancialProfile`은 분석 대상자당 하나만 연결한다. 월 필수생활비, 월 실수령 소득, 소득공백 개월, 보유 비상자금과 그중 사용할 금액, 유급휴가 지원금, 대출 잔액, 부양가족 수, 가족 월 지출, 가족 지원 개월, 사용할 유동자산을 nullable 값으로 저장한다. `20260908_0012`부터 아동의 보호자 월 소득 감소·월 추가 돌봄비와 노년기의 분석에 사용할 월 연금·지속소득·월 의료돌봄 본인부담을 별도 nullable 필드로 저장한다.

빈칸은 미입력(`NULL`)이며 0원이 아니다. 계산에 필요한 핵심값이 없으면 결과를 만들지 않는다. `emergency_fund_to_use_won`은 `emergency_fund_available_won`보다 클 수 없다. 이 모델은 원본 증권 추출값이나 사용자 확정 담보를 수정하지 않는다.

생애단계 필드는 사용자 확인값만 저장한다. 아동 본인의 소득, 보호자의 손실, 노년기의 연금이나 장기요양 본인부담을 연령·성별·공식 제도만으로 추정하지 않는다. 대상자의 생애단계가 바뀌면 현재 단계에 필요한 입력만 계산에 사용한다.

## 구현 추가: AnalysisResultSnapshot (2026-09-07)

`AnalysisResultSnapshot`은 분석 대상자, 결과 규칙 버전, 직렬화한 결과 보고서와 SHA-256 입력 지문, 생성 시각을 보존한다. 사용자가 결과 화면에서 저장을 요청할 때만 추가되며 기존 원본·추출값·확정값·경제정보를 수정하지 않는다. 동일 입력은 같은 지문을 갖지만 기록 자체는 별도로 남겨 저장 시점을 구분한다.

## 구현 추가: PdfAudit (2026-09-03)

문서별 추가 기록 방식으로 버전, 입력 지문, 검토 범위·검산 결과·담보 ID별 오류·독립 원문 개수·미확인 조건 수를 보존한다. 입력 지문은 원본 파일의 현재 해시, 저장 해시, 페이지 근거, 추출 셀·좌표·값, 사용자 수정값·상태, 추출 버전에 묶인다. 기존 `confirmed_fields`는 자동 채우지 않는다.

`summary_ready`는 지원하는 표 읽기 검산 범위, `analysis_ready`는 후속 조건 검토 범위다. 현재 후자는 항상 False다. 이전 검산 이력은 보존하되 현재 지문과 맞지 않으면 화면·요약 경로에서 사용하지 않는다. 0004와 0005 마이그레이션은 각각 검산과 조건 근거 표를 추가한다. 기존 `create_all` DB는 모든 기존 표를 확인한 뒤 2026-09-04에 Alembic 기준점을 0005로 기록했다.
