# 분석 및 담보 처리 규칙

## 분석 전 최종 관문

계산 전에 현재 원본에 대한 담보 표 검산, 대상자 확인, 보험회사·상품 확인, 필요한 페이지 OCR, 담보별 보장내용 근거, 표 밖 공통 조건의 적용 범위, 갱신·주계약/특약·정액/실손·지급횟수를 모두 검사한다. 실패 항목이 하나라도 있으면 결과를 만들거나 저장하지 않는다. HWPML과 PDF가 같은 계약 후보이면 별도 보험으로 합산하지 않는다.

부분 마스킹 계약 식별값과 상품명의 해시 지문으로 같은 계약임이 확인된 조회자료는 사용자가 명시적으로 한 대상자에게 묶음 연결할 수 있다. 대상자나 개인정보를 지문에서 추론하지 않는다. 같은 계약의 여러 파일에 동일 위험 담보가 겹치면 대응자금으로 두 번 합산하지 않고 중복 여부 확인 전까지 판단을 보류한다.

## 안전 기본값과 값 계층

확실하지 않으면 합산하거나 확정하지 않는다. `미확인`, `확인 필요`, `판단 보류`는 안전한 제품 상태다.

값은 다음처럼 분리한다.

1. `extracted`: PDF/OCR/AI가 읽은 원본 후보
2. `confirmed`: 사용자가 원문과 대조해 확정한 값
3. `auto_checked`: 원본 해시·근거 위치·검증기 버전에 묶인 자동 검산 범위. 현재는 표 전사·금액·기간만 검산하며 분석용 조건 확인을 대신하지 않는다.
4. `derived`: 검증된 입력과 버전이 있는 규칙으로 계산한 값

사용자 수정은 원본 후보를 덮어쓰지 않는다. 담보명, 금액·단위, 보험기간, 급부 유형, 정액/실손, 지급 횟수 등 핵심값이 검증되지 않았으면 계산에서 제외하거나 판단을 보류한다.

## 담보 분류 축

표준 담보명만으로 합산을 결정하지 않고 다음을 함께 비교한다.

- 위험·질병 범위
- 급부: 진단, 수술, 입원, 사망, 장해, 간병
- 보상: 정액형, 실손형, 혼합/미확인
- 지급: 최초 1회, 기간별 1회, 일별, 반복, 미확인
- 금액 단위와 통화
- 보장 시작·종료, 갱신
- 면책·감액·제외 조건
- 주계약/특약

## 합산 규칙

정액형이고, 같은 표준 담보·위험 범위·급부이며, 같은 분석 시점에 유효하고, 금액·단위·지급 조건이 확인된 경우에만 “명목상 정액 보장 합계” 후보가 된다. 이 합계는 실제 지급액을 보장하지 않는다.

다음은 합산하지 않는다.

- 실손끼리 또는 실손과 정액
- 일반암과 유사암
- 뇌혈관질환과 뇌졸중
- 허혈성심장질환과 급성심근경색
- 진단비와 수술비·입원비
- 최초 1회와 반복 지급액을 하나의 총액으로 표현하는 경우
- 기간이 유효하지 않거나 금액 단위·범위·조건이 미확인인 경우

합산하지 않는 항목은 나란히 표시하고 범위 차이와 확인할 조건을 설명한다.

## 금액과 기간

- 원문 숫자, 원문 단위, 정규화한 원 단위 값을 모두 저장한다.
- `10,000`처럼 단위가 불명확하면 계산하지 않는다.
- 보험기간과 납입기간을 별도 유지한다.
- 종신, 연령 만기, 날짜 만기를 구분한다.
- 갱신형은 현재 기간과 갱신 사실을 표시하며 장래 갱신을 보장하지 않는다.

## 자금공백 계산

### 중대질환 생활자금

```text
필요 생활자금 = 월 필수생활비 × 사용자 선택 소득중단 개월
대응 가능자금 = 해당 위험의 확정 정액 진단비
              + 사용하기로 한 비상자금
              + 금액이 확인된 유급휴가·회사 지원
추정 자금공백 = max(0, 필요 생활자금 - 대응 가능자금)
```

월소득은 소득공백의 맥락과 입력 검증에 사용하되 생활비와 이중 계산하지 않는다.

아동·청소년은 본인의 소득을 가정하지 않고 다음 식을 사용한다. 보호자 소득 감소와 추가 돌봄비가 빈칸이면 계산을 보류하며, 0원은 사용자가 실제로 추가 공백이 없다고 확인한 값이다.

```text
필요 생활자금 = (보호자 월 소득 감소액 + 아동 월 추가 돌봄비) × 사용자 선택 대비개월
대응 가능자금 = 해당 위험의 확정 정액 진단비 + 사용하기로 한 비상자금 + 확인된 유급휴가·회사 지원
```

노년·은퇴기는 근로소득을 가정하지 않고 다음 식을 사용한다. 연금·지속소득은 전체 수령액이 아니라 사용자가 이 시나리오에 사용한다고 입력한 월 금액만 반영한다. 장기요양 등 공적제도 금액은 자동 추정하거나 차감하지 않는다.

```text
필요 생활자금 = (월 필수생활비 + 월 의료·돌봄 본인부담) × 사용자 선택 대비개월
대응 가능자금 = 해당 위험의 확정 정액 진단비 + 사용하기로 한 비상자금
              + 분석에 사용할 월 연금·지속소득 × 대비개월
```

아동·노년 분기도 `max(0, 필요 생활자금 - 대응 가능자금)`을 사용한다. 큰 자금공백 보조 표시는 해당 분기의 월 시나리오 필요액 3개월분을 사용하며, 공식 권장액이나 가입 권유가 아니다.

### 의료비

실손을 가입금액처럼 차감하지 않는다. 세대·자기부담·한도·범위가 확인되지 않으면 정량 공백 대신 정성 상태와 확인 필요 항목을 표시한다. 공적제도도 확정 현금처럼 단순 차감하지 않는다.

### 사망보장 생활비 지속기간

사망보험금이 확인된 경우 부족액과 별도로 사용자가 이해하기 쉬운 기간을 표시한다.

- 부채 상환 전 지속기간 = 확정 사망보험금 ÷ 가족 월 필수생활비
- 부채 상환 후 지속기간 = max(0, 확정 사망보험금 − 대출잔액) ÷ 가족 월 필수생활비
- 공적 최소 참고선 지속기간 = max(0, 확정 사망보험금 − 대출잔액) ÷ 해당 가구원 수의 생계급여 최저보장수준

기간은 완전히 충당되는 개월 수만 보수적으로 표시한다. 생계급여 선정기준은 평균 생활비나 보험 권장액이 아니며, 사용자의 실제 생활비를 대체하지 않는다. 물가·이자·세금·장례비는 반영하지 않은 단순 비교임을 함께 표시한다.

### 사망과 가족생활

```text
필요자금 = 대출잔액 + 가족 월 필수생활비 × 가족생활 유지 희망개월
대응자금 = 확정 사망 정액보험금 + 사용 범위에 포함한 즉시 금융자산
추정 자금공백 = max(0, 필요자금 - 대응자금)
```

부양가족이나 핵심 입력이 없으면 자동으로 충분 판정하지 않는다.

### 장기 위험

후유장해·간병·치매는 초기에는 보장 현황, 반복 지급과 사용자 시나리오를 분리한다. 검증된 비용 가정 없이 단일 권장액을 만들지 않는다.

## 결과 상태

- 자금공백 없음: 계산 공백 0원. `충분`·`과잉`으로 단정하지 않음.
- 일부 자금공백 / 큰 자금공백: D-006 사용자 결정에 따라 공백이 월 필수생활비 3개월분 이상이면 큰 자금공백으로 보조 표시한다. 공식 권장기준이 아닌 앱 표시 기준이다.
- 정보 부족으로 판단 보류: 핵심 입력·확정 담보·규칙 부족.

D-006과 다른 임의 경계를 구현하지 않는다. 계산 엔진과 경계 테스트는 구현 완료 상태이며, 모든 결과에 사용한 값, 제외 이유, 규칙 버전, 산식, 앱 시나리오임을 표시하고 보험금 지급을 확정하지 않는다.

## 중복과 유지 목적 검토

중복 가능성은 동일한 위험·급부·보장 범위·보험기간·갱신·지급 횟수가 확인된 경우에만 표시한다. 금액이 크거나 같은 표준 담보라는 이유만으로 축소 대상으로 판정하지 않는다.

`유지 목적 검토 대상`은 다음 정보를 함께 보여줄 수 있을 때만 사용한다.

- 겹치는 담보와 각각의 원문 조건
- 정액형/실손형과 합산 가능 여부
- 보험기간·갱신·지급 횟수 차이
- 현재 보험료와 남은 납입기간(확인된 경우)
- 해지·감액 시 보장 상실 및 향후 재가입이 어려울 수 있다는 한계

앱은 해지나 감액 결정을 대신하지 않는다. 정보가 부족하면 중복 가능성만 표시하고 판단을 보류한다.

## 이름 기반 분류 후보 (2026-09-07)

15개 표준 담보군은 이름 기반 탐색용 후보이며 지급 조건 확인이나 합산 승인이 아니다. `coverage_classification.py`는 원문명을 보존하고 사용자 수정 이름이 있으면 따로 표시한다. 자동차·법률·골절 등 15개 표준군 밖의 담보는 ‘표준군 밖’으로 분리하며, 이것은 보장이 없거나 추출 실패라는 뜻이 아니다. 여러 표준군이 검출되거나 소액암·특정암·재진단암·3대암처럼 범위가 불명확하면 분류 확인 필요로 남긴다. 실손 입원은 실손군으로 표시하고, 명시적 유사암 제외 문구는 양성 보장 후보로 세지 않는다. 분류 페이지는 최신 표 검산을 요구하며 원본 변경 시 차단한다. 실제 통합에는 대상자·계약 중복·조건 검증을 별도로 구현해야 한다.

통합 준비 화면은 표준 담보군 후보를 통합 가능·확인 후 검토·표준군 밖으로만 나눈다. 통합 가능은 사용자 원문 대조, 정액형 확인, 갱신·지급횟수·주계약/특약·보험기간 확인이 끝났다는 뜻이며, 이 단계에서도 금액을 합산하지 않는다. 같은 계약의 다른 파일 후보는 별도 보험으로 합산하지 않는다.

다문서 통합은 같은 분석 대상자에게 연결된 서로 다른 PDF만 비교한다. 같은 표준군의 확정 정액형 담보가 서로 다른 문서에 있고, 급부·보험기간·갱신·지급횟수가 모두 같을 때만 ‘명목상 정액 보장 합계’를 표시한다. 한 문서 안의 여러 행, 실손형, 미확정 담보, 다른 대상자의 문서, 중복 계약 후보는 합산하지 않는다.

## 중대질환 생활자금 공백 계산 기반 (2026-09-07)

핵심 입력(월 필수생활비, 소득공백 개월, 사용할 비상자금, 유급휴가 지원금)과 원문 대조가 끝난 확정 진단비가 모두 있을 때만 다음 식을 적용한다.

`max(0, 월 필수생활비 × 소득공백 개월 − 확정 진단비 − 사용할 비상자금 − 유급휴가 지원금)`

확정 진단비는 정액형·동일 대상자·중복 계약 제외·지급 조건 일치 확인을 통과한 담보만 사용할 수 있다. 실손형, 미확정 담보, 서로 다른 지급 조건의 담보는 제외 이유와 함께 표시한다. 현재 계산 함수는 입력 부족 시 금액을 추정하지 않고 `정보 부족으로 판단 보류`를 반환한다.

결과 화면은 일반암·유사암·뇌혈관질환·뇌졸중·허혈성심장질환·급성심근경색을 별도 시나리오로 계산한다. 서로 다른 질병군의 진단비를 합쳐 하나의 자금공백으로 표시하지 않는다. 한 문서에 같은 질병군 담보가 여러 개면 지급 조건을 더 확인할 때까지 계산하지 않는다.

질병사망과 상해사망도 각각 가족생활 시나리오로 계산한다. 대출잔액과 가족 월 필수생활비·유지기간을 필요 자금으로, 해당 위험의 확정 정액 사망보험금과 사용할 유동자산을 대응 자금으로 쓴다. 질병사망과 상해사망, 또는 서로 다른 지급 조건의 사망 담보는 합산하지 않는다.

실손의료비는 정량 공백 계산에서 제외하고, 원문 대조 확정된 담보 현황만 표시한다. 자기부담금·한도·보장 범위가 확인되지 않은 실손을 현금이나 정액 진단비처럼 차감하지 않는다. 후유장해·간병·치매는 반복 지급과 세부 범위가 확인되기 전까지 보장 현황과 원문 근거만 표시한다.
